Mutex state

MUTEX = 0 means unlocked. MUTEX = 1 means locked. Only the thread that successfully changes the state from 0 to 1 may enter the critical section.

What TSL does

TSL REGISTER,MUTEX performs two actions as one indivisible hardware operation: it copies the old value of MUTEX into REGISTER, and then stores 1 in MUTEX.

Atomic means no other thread can observe or interrupt the operation halfway through. If REGISTER receives 0, the caller acquired an unlocked mutex. If it receives 1, another thread already held the mutex.

Simple implementation

mutex_lock

mutex_lock:
    TSL  REGISTER, MUTEX
    CMP  REGISTER, #0
    JZE  ok
    CALL thread_yield
    JMP  mutex_lock
ok:
    RET

mutex_unlock

mutex_unlock:
    MOVE MUTEX, #0
    RET

Uncontended

A thread sees the old value 0, atomically changes the mutex to 1, and enters the critical section.

Contended

A thread receives the old value 1, yields the CPU, and tries again after another thread runs.

Unlock

The owner stores 0 in the mutex, making the critical section available to a future contender.

Why ordinary check-then-set fails

If reading the lock and setting it are separate instructions, a context switch can occur between them. Two threads can both read 0 before either stores 1, so both believe they acquired the mutex and both enter the critical section.

The mutex variable alone does not provide mutual exclusion. The transition from unlocked to locked must be atomic.

Yielding versus spinning

A pure spinlock repeatedly executes the test-and-set instruction while waiting, consuming CPU time. This example calls thread_yield after a failed attempt so another runnable thread can use the processor. The waiting thread still retries later, and this simple loop does not guarantee fairness.

Limitations of the simple example

  • It does not track or verify lock ownership before unlocking.
  • It provides no fairness guarantee, so a thread may repeatedly lose the race.
  • Production mutexes usually maintain a wait queue and block threads rather than relying only on repeated retries.
  • Real implementations also require architecture-appropriate memory-ordering guarantees.

Discussion questions

  • Why must TSL copy the old mutex value before setting it to 1?
  • What does REGISTER = 0 tell the caller?
  • Why does a failed thread yield before retrying?
  • How can two threads enter the critical section when check and set are separate?
  • Why might this implementation be unfair?
