Teaching notes

The working set is a set of unique pages used recently. Accessing a page twice does not count it twice. A page can leave the set when its last access ages out of the window.

This view knows exact access times. The window includes both endpoints: time − τ ≤ access time ≤ time. Each reference occurs one virtual second apart. Virtual time counts time the process runs, not time waiting for I/O.

Working-set membership is a keep/evict preference, not an instruction to evict immediately. If the active set cannot fit in RAM, repeated faults can cause thrashing.

The WSClock decision rules
  1. R = 1: clear R, refresh the stored time to now, then advance.
  2. R = 0 and age ≤ τ: keep the page and advance.
  3. R = 0 and age > τ, M = 0: evict this old, clean page.
  4. R = 0 and age > τ, M = 1: schedule writeback and continue scanning.

Slide connection: Current time is 2204. Page D starts with stored time 2014 and R = 1. The scan changes it to time 2204 and R = 0, then advances to page E (time 1213, R = 0). The slide does not specify M or τ; the default example adds M = 0 and τ = 500.

Full-scan behavior: When writes are pending, pause and complete them before rescanning. If every page is recent, this demonstration stops and reports no old victim rather than evicting a recent page. Real implementations need a fallback or memory/load adjustment.

This is a frozen page-fault snapshot: virtual time remains 2204 while the process waits. No new page accesses occur during scanning; writeback completes only when you click the write button. This makes bit changes and decisions easy to follow.
