Pause and predict
  1. For address 2,500, what are the page number and offset?
  2. When a page moves to a different frame, does its offset change?
  3. Does a TLB miss always require disk access?
  4. When RAM is full, which page will FIFO or LRU evict?

Key idea: Virtual pages can occupy nonconsecutive RAM frames. The page number becomes a frame number; the offset stays unchanged.

Instructor notes and classroom sequence

Begin in mode 1. Step through 2,500 (page 2 → frame 3, physical address 3,524), then 3,500 (page 3 is absent). An empty frame is available for the first fault.

In mode 2, repeat an address to see a TLB hit. Access a new resident page to show a TLB miss without disk access. Mode changes reset the demonstration.

In mode 3, use the example sequence: pages 0, 3, 0, 4. After the first three references, FIFO evicts page 0 while LRU evicts page 1. Change policy and replay to compare.

The animation models legal read accesses, one single-level page table, demand paging, a two-entry LRU TLB, and clean backing copies. It omits permissions, dirty-page writeback, multiple processes, and real hardware timing. Initial load/use order is page 0, then 1, then 2. Reset clears all statistics.

Basic and TLB modes stop before replacement if RAM fills. Switch to mode 3 to teach eviction. A fault pauses before disk loading; the original access resumes after the mapping is updated.
