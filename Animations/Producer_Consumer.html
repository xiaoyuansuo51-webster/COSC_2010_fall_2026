Concept

The producer creates items and places them in a shared, finite buffer. The consumer removes those items. Coordination is necessary because the producer must wait when the buffer is full, and the consumer must wait when the buffer is empty.

The animation displays five slots for clarity. The original pseudocode uses N = 100.

Normal execution

  1. The consumer observes that the buffer is empty and sleeps.
  2. The producer creates and inserts an item.
  3. count changes from 0 to 1.
  4. The producer wakes the sleeping consumer.
  5. The consumer removes and processes the item.

Lost wakeup

  1. The consumer observes count == 0.
  2. A context switch occurs before sleep().
  3. The producer inserts an item and calls wakeup(cons).
  4. The consumer is not sleeping yet, so the wakeup has no effect.
  5. The consumer resumes, executes sleep(), and may remain asleep indefinitely.

An item is available, but the consumer cannot process it.

Why the problem occurs

Checking count and entering the sleeping state are separate operations. A context switch can occur between them. The program therefore has a race condition: its behavior depends on the exact timing of the producer and consumer.

Standard semaphore solution

Semaphores make checking resource availability and blocking part of one atomic synchronization operation. empty counts unused slots, full counts available items, and mutex protects the buffer while it is being changed.

Producer

while (true) {
    item = produce_item();
    wait(empty);
    wait(mutex);
    insert_item(item);
    signal(mutex);
    signal(full);
}

Consumer

while (true) {
    wait(full);
    wait(mutex);
    item = remove_item();
    signal(mutex);
    signal(empty);
    consume_item(item);
}

Discussion questions

  • Why is the buffer still nonempty when the consumer goes to sleep in the lost-wakeup scenario?
  • Which two operations need to behave atomically?
  • What happens when the producer is faster than the consumer and the buffer becomes full?
  • What roles do empty, full, and mutex play in the semaphore solution?
